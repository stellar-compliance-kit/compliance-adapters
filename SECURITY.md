# Security Policy

We take security reports seriously. If you discover a vulnerability in any of the packages in this repository
(`sep10-auth`, `sanctions-oracle`, `horizon-listener`), please report it following the guidance below.

## Reporting

- Preferred: Open a private GitHub Security Advisory for this repository (recommended) or contact the maintainers at `security@stellar.org`.
- If you cannot use GitHub Security Advisories or e-mail, create a private/hidden issue and mark it `security` (do not include exploit details in a public issue).

When reporting, include:
- A clear description of the issue and steps to reproduce
- Affected package(s) and versions
- Impact assessment and suggested mitigation (if possible)

## Response Expectations

- We will acknowledge receipt within 3 business days.
- High/critical issues: we aim to provide a remediation timeline within 7 calendar days.
- Medium/low issues: we will triage and provide expected timelines within 14 calendar days.

## Supported Versions

We consider the latest minor/patch releases of each package to be supported for security fixes. If you are unsure
whether your version is supported, indicate the exact version in your report and we will clarify.

## Public Disclosure

We ask reporters to allow maintainers reasonable time to respond and release a fix before public disclosure.
If you have coordinated disclosure terms, indicate them in your report.

## PGP

We do not currently publish a PGP key; if you need to send sensitive information, contact us first and follow the channel
we provide.

---
This policy is intended to help external researchers report vulnerabilities responsibly.
